# 智能惠农信贷系统 —— 项目结构与代码说明

> 本文只讲**"代码分成哪几类、每类干什么"**，不重复启动步骤与接口清单——那些看根目录 `README.md`。

## 一、总体结构

系统分三块，数据库只有一份，在 MySQL 里；前端不直接碰数据库。

```
┌────────────────────────┐        ┌──────────────────────────────┐        ┌──────────────┐
│  前端 smart-agri-loan-vue │        │  后端 smart-agri-loan-server    │        │              │
│  原生 HTML + Vue 3       │  HTTP  │  Spring Boot 3.2 (Java 17)     │  JDBC  │    MySQL 8   │
│  （无构建，静态服务即可）  │ ─────► │  Controller → Service → Repo   │ ─────► │  7 张业务表   │
│  JWT 放在 localStorage   │  JWT   │  Spring Security + JWT         │        │  utf8mb4     │
└────────────────────────┘        └──────────────────────────────┘        └──────────────┘
```

- 前端：`e:\ai-coding\smart-agri-loan-vue`，起静态服务（如 `python -m http.server 8090`）即可运行。
- 后端：`e:\ai-coding\smart-agri-loan-server`，`mvn spring-boot:run`，端口 8080。
- 数据库：库名 `smart_agri_loan`，**需先执行 `db/schema.sql` 建库建表**，服务不自动建库。

## 二、数据库层

| 文件 / 内容 | 作用 |
| --- | --- |
| `db/schema.sql` | 7 张表的建库建表脚本，**首次启动前必须执行**。内含 `DROP TABLE`，重跑等于清空业务数据 |
| `config/DataInitializer.java` | 演示数据**由 Java 代码构造后经 JPA 写库**，不是 SQL 脚本；仅当表为空时执行 |

### 7 张表

| 表名 | 对应实体 | 存什么 |
| --- | --- | --- |
| `sys_user` | `User` | 农户 / 农业企业 / 审批人员，含信用积分、五维评分、余额、启用状态 |
| `loan_product` | `Product` | 贷款产品：利率、期限、额度区间、还款方式、准入门槛、上下架 |
| `agri_news` | `News` | 惠农资讯，正文按 `\n` 分段存储 |
| `loan_application` | `LoanApplication` | 贷款申请单，含全流程各阶段时间戳与审批意见 |
| `loan_application_log` | `ApplicationLog` | 单张申请单的流转轨迹（提交 → 审批 → 签约 → 放款 → 结清） |
| `credit_log` | `CreditLog` | 信用积分变动明细 |
| `sys_operation_log` | `OperationLog` | 由 AOP 切面自动写入的操作审计日志 |

## 三、后端代码分类

依赖方向自上而下：`controller → service → repository → domain`，旁挂 `security / aop / common / support`。

| 包 | 职责 | 主要文件 |
| --- | --- | --- |
| （根包） | 启动入口 | `AgriLoanApplication` |
| `config` | 启动期动作 | `DataInitializer`（种子数据） |
| `controller` | **收 HTTP 请求，只做转发**，不写业务规则 | `AuthController`、`UserController`、`ProductController`、`NewsController`、`ApplicationController`、`CreditController`、`AccountController`、`OperationLogController`、`AdminController` |
| `service` | **所有业务规则**集中在这里 | `ApplicationService`（贷款全流程）、`CreditPolicyService`（信用等级策略，全站"因人而异"的唯一来源）、`ProductService`、`NewsService`、`UserService`、`AuthService`、`CreditService`、`OperationLogService` |
| `repository` | **只负责读写数据库**，SQL 由 Spring Data JPA 生成 | `UserRepository`、`ProductRepository`、`NewsRepository`、`LoanApplicationRepository`、`CreditLogRepository`、`OperationLogRepository` |
| `domain` | 实体（数据库表的 Java 版）与枚举 | 实体：`User`、`Product`、`News`、`LoanApplication`、`ApplicationLog`、`CreditLog`、`OperationLog`、`Auditable`（公共审计字段）；枚举：`Role`、`ProductType`、`NewsCategory`、`ApplyStatus` |
| `dto` | 出入参对象，**不把实体直接暴露给前端** | 出参：`UserDTO`、`ProductDTO`、`NewsDTO`、`ApplicationDTO`、`CreditInfoDTO`、`PolicyDTO`、`DimensionDTO`、`AuthResponse`；入参：`LoginRequest`、`RegisterRequest`、`ApplicationCreateRequest`、`AuditRequest`、`ProductSaveRequest`、`NewsSaveRequest`、`UserSaveRequest` |
| `security` | 认证 + 授权 | `JwtService`（签发/校验 token）、`JwtAuthenticationFilter`（解析请求头）、`SecurityConfig`（权限矩阵）、`UserDetailsServiceImpl`（查库取用户）、`LoginUser`、`SecurityUtils` |
| `aop` | 操作留痕，业务代码零侵入 | `@OpLog` 注解 + `OperationLogAspect` 切面 |
| `common` | 统一响应与异常 | `ApiResponse`（`{code,message,data}`）、`BusinessException`、`GlobalExceptionHandler`、`PageResult` |
| `support` | 实体 → DTO 转换（顺带计算自适应字段） | `DtoMapper` |

### 各层"不该做什么"

| 层 | 禁止 |
| --- | --- |
| `controller` | 写业务判断、直接调 `repository` |
| `service` | 直接操作 `HttpServletRequest`（除日志切面外） |
| `repository` | 写业务逻辑 |
| 任意层 | 把 `domain` 实体直接当返回值给前端 |

## 四、前端代码分类

原生 HTML + Vue 3（`vendor/vue.global.prod.js` 本地引入），**无需构建打包**。

| 分类 | 文件 | 作用 |
| --- | --- | --- |
| 入口 | `index.html` | 首页 |
| 页面 | `pages/*.html` × 9 | `login`、`products`、`news`、`apply`、`apply-result`、`my-apply`、`audit`、`credit`、`op-logs` |
| **接口层** | `js/api.js` | **与后端的唯一出口**：拼 URL、自动带 `Authorization: Bearer`、统一处理 401、把后端数据组装成页面认识的形状 |
| 旧数据层 | `js/db.js` | 早期用 `localStorage` 假数据的版本；现已被 `api.js` 兼容，页面里的 `DB.getDB()` 写法无需改动，属历史遗留 |
| 常量 | `js/constants.js` | 状态、信用等级、分类等中文常量 |
| 公共件 | `js/components.js`、`js/utils.js` | 导航栏、弹窗等公共组件与格式化工具 |
| 页面逻辑 | `js/home.js`、`login.js`、`products.js`、`news.js`、`apply.js`、`apply-result.js`、`my-apply.js`、`audit.js`、`credit.js`、`op-logs.js` | 一个页面配一个脚本 |
| 样式 | `css/common.css`、`css/pages.css`、`css/auth.css` | 公共样式 / 业务页面 / 登录注册 |
| 依赖 | `vendor/vue.global.prod.js` | Vue 3 生产版，离线可用 |
| 测试 | `tests/e2e-integrated.spec.js` 等 | Playwright 端到端用例与用例清单 |

> 约定：页面脚本**不得**直接 `fetch`，一律走 `API.xxx`；也**不得**直接读 `localStorage` 存业务数据。

## 五、一条请求的完整链路

以"提交贷款申请"为例：

```
apply.js
  → api.js                      POST /api/applications（带 Bearer token）
  → JwtAuthenticationFilter     校验 token，写入当前登录人
  → SecurityConfig              判断角色是否有权访问该接口
  → ApplicationController       接参、@Valid 校验格式
  → ApplicationService          业务：准入判断 → 落库 → 写流转日志
  → LoanApplicationRepository   → MySQL
  同时 @OpLog 切面                → sys_operation_log 留痕
```

## 六、常见改动该往哪加

| 你要做的事 | 需要动的文件 |
| --- | --- |
| 新增一个接口 | `controller` 加方法 → `service` 加业务 → 需要的话 `repository` 加查询；`SecurityConfig` 按需配权限 |
| 数据库加字段 | `domain` 实体加字段 → `dto` 补字段 → `DtoMapper` 补赋值；表结构由 `ddl-auto=update` 自动加列 |
| 加一个页面 | `pages/` 加 html → `js/` 加脚本 → `js/api.js` 加对应请求方法 |
| 调整信用等级规则 | 只改 `CreditPolicyService`（全站唯一策略来源） |
| 加种子数据 | 只改 `DataInitializer`（表为空时才会执行） |
| 让某操作留痕 | 在 service 方法上加 `@OpLog(module=..., action=..., target="#参数名")` |
